# Отчет по лабораторной работе №1 и 2 "Разработка Telegram-бота для записи на маникюр"

## Структура проекта

Проект имеет следующую структуру:

- `bot.py` — основной файл бота, содержащий логику клиентского и административного режимов;
- `schema.sql` — SQL-скрипт создания таблиц базы данных;
- `add_slots.sql` — SQL-скрипт массового добавления временных окон;
- `add_slots.py` — вспомогательный Python-скрипт для добавления слотов;
- `.env` — файл с секретами (не попадает в репозиторий);
- `.env.example` — шаблон конфигурации;
- `.gitignore` — список файлов, исключённых из системы контроля версий;
- `manicure.db` — файл базы данных SQLite.

## Проектирование базы данных

База данных содержит четыре таблицы:

- `clients` — клиенты бота (Telegram ID, имя пользователя, ФИО, дата регистрации);
- `procedures` — список процедур с указанием названия, стоимости и длительности;
- `time_slots` — доступные временные окна, привязанные к конкретной дате;
- `bookings` — записи клиентов, связывающие клиента, процедуру и временное окно, со статусом заявки.

Статусы заявок: `pending` (ожидает подтверждения), `accepted` (принята), `declined` (отклонена), `cancelled` (отменена клиентом).

## Реализация клиентского режима

После команды `/start` клиент получает главное меню с двумя кнопками: «Записаться» и «Мои записи». Кнопка администратора отображается только пользователям, чьи Telegram ID указаны в списке администраторов, — таким образом, для обычных клиентов административный режим полностью невидим.

Процесс записи реализован как последовательный диалог:

1. выбор даты из ближайших двух недель;
2. выбор свободного времени (не занятого другими заявками в статусах `pending` или `accepted`);
3. выбор процедуры с отображением цены в рублях;
4. ввод комментария (необязательно);
5. подтверждение записи.

После подтверждения заявка сохраняется в базе со статусом `pending`, а мастеру отправляется уведомление с данными клиента.

## Реализация административного режима

Административный режим активируется кнопкой «Режим мастера», которая отображается только у пользователей с ID из списка `ADMIN_TELEGRAM_IDS`. При нажатии бот запрашивает пароль. При неверном пароле или попытке входа от имени обычного пользователя бот отвечает стандартным сообщением «Пожалуйста, воспользуйтесь меню», не раскрывая факта существования административного режима.

Функционал мастера:

- просмотр записей на текущий день;
- просмотр всех новых заявок со статусом `pending`;
- принятие или отклонение заявки (клиент получает уведомление автоматически);
- добавление новых временных окон на произвольные даты;
- просмотр занятости слотов на ближайшие дни.

## Управление секретами

Токен бота и пароль администратора вынесены в файл `.env` и не попадают в систему контроля версий. Файл `.gitignore` исключает из репозитория следующие категории файлов: секреты (`.env`), базу данных (`*.db`), виртуальное окружение (`venv/`), кэш Python (`__pycache__/`), файлы редакторов и логи.

Для удобства развёртывания создан файл-шаблон `.env.example`, содержащий перечень необходимых переменных без конкретных значений.

Дополнительно реализован pre-commit hook, проверяющий staged-файлы на наличие строк, похожих на токен Telegram-бота, и блокирующий коммит при обнаружении совпадений.

## Заполнение расписания

Для наполнения базы данных временными окнами разработан SQL-скрипт, использующий рекурсивный CTE. Скрипт создаёт слоты с 12:00 до 18:00 на 30 дней вперёд. За счёт уникального индекса `UNIQUE(slot_date, slot_time)` и конструкции `INSERT OR IGNORE` скрипт идемпотентен — повторный запуск не создаёт дубликатов.

## Возникшие проблемы и их решение

В ходе разработки были выявлены и устранены следующие проблемы:

**Пустой список временных окон** — клиентский интерфейс корректно отображал отсутствие слотов, так как таблица `time_slots` изначально пуста. Решено добавлением SQL-скрипта массового заполнения расписания.

## Выводы

В ходе работы разработан полнофункциональный Telegram-бот для записи клиентов к мастеру маникюра. Реализованы клиентский и административный режимы с разделением доступа по Telegram ID и паролю. Обеспечена безопасная работа с секретами через переменные окружения и систему контроля версий. Применён идемпотентный SQL-скрипт для наполнения расписания. Бот готов к практическому использованию и дальнейшему расширению функциональности: напоминания клиентам, отмена записи клиентом, интеграция с платёжными системами.
